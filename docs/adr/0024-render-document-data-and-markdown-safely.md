# 24. Render document data and markdown safely

Date: 2026-11-06

Status: Accepted

## Context

Several places in 1.6.30 put text that an outsider can influence into the page as HTML. The graph panel's node title, listed below with the chart labels, is not one of them: that panel was added after 1.6.30, and the title is escaped so that it starts safe.

- **Document fields.** The document viewer wrote the title and the content with `ng-bind-html-unsafe`. The full text search panel did the same for the body when highlighting is off, and its highlighted body only went through `$sanitize` after a filter that escaped nothing. The table panel wrote the hyperlink column through the `urlLink` filters without escaping the text around the address, and built the image of an image column as `<img src="...">` with the value inside the quotes, where a `"` in the value ends the attribute. Anyone who can get a value into an indexed document (a user agent in a log, a title in a crawl) runs script for every person who views that document in a panel.
- **Markdown.** The text panel escapes `<`, `>` and `&` in the markdown source and then writes what the converter (Showdown) produced with jQuery `.html()`. Showdown copies the address of a link or image into `href` or `src` without checking the scheme and without escaping a double quote, so `[x](javascript:...)` runs on click and `![i](a" onerror="...)` adds an attribute.
- **Alerts.** The alert container in `index.html` wrote the alert text with `ng-bind-html-unsafe`. Several alerts that exist in 1.6.30 quote a value that comes from the dashboard or from the dashboard list: "Dashboard Saved" (title, or the id in the dashboard control panel), "Dashboard Deleted" and "Dashboard Not Found" (an id from the list of saved dashboards, which anyone who can save a dashboard names), "Local Default Set" (the dashboard title) and the gist alert (a link). The failed-request alerts added since escape their values already (see 0014).
- **Chart labels written as HTML.** The terms pie labels (the term is appended by flot's pie plugin as HTML) go through `kbn.pieLabelHtml`, which escapes the term. The graph panel's node title, which vis 4.21.0 writes with `innerHTML`, is escaped.
- **Tooltips.** Chart tooltips and the field-list tooltips put series names, queries and field values into HTML (a Bootstrap tooltip with `html: true`, a flot tooltip written with `.html()`, a leaflet label).

Inside Fusion this code runs in the admin origin with the viewer's session; standalone it runs in the Banana origin. The same data reaches the page in every hosting mode.

AngularJS is 1.0.8 and stays there. In that version `ng-bind-html` and the `$sanitize` service come from the `ngSanitize` module (`angular-sanitize.js`, already vendored, already a dependency of the application and already used by the text panel's HTML mode, the inspector and the modal dialogs). `$sanitize` keeps a fixed list of elements and attributes, drops event handlers, and keeps `href`/`src` only for `http`, `https`, `ftp`, `mailto` and `#`. It has no hook to choose other schemes.

## Options considered

1. **Escape every value and keep `ng-bind-html-unsafe`.** Rejected as the only measure: every new sink would need its own escaping, and one missed value is a hole. It is used where the output must contain markup that `$sanitize` would remove (see the table image column below), but never alone elsewhere.
2. **Send everything through `ng-bind-html`.** Rejected as the only measure. `$sanitize` removes the `style` attribute and relative and `data:` image addresses, which the table's image column needs. It also keeps harmless but unwanted markup: a document that holds `<b>x</b>` would still be shown as bold, and an `<img>` without an address would still appear, although markup in a document is data and not formatting.
3. **Turn alerts into plain text.** Rejected: two alerts that exist in 1.6.30 need markup (the gist alert holds a link, and the alert for a dashboard file that cannot be loaded holds `<i>`), and showing them as text would show the tags to people. The alerts that 0014 already escapes at the call site would also show `&lt;` instead of `<` once the container escaped them again.
4. **Edit the vendored Showdown (two identical copies) to check the address.** Rejected: it changes third-party files that are shipped under their own licence notice, and the same change would have to be made again for the second copy and for each update.
5. **Add a sanitizer library such as DOMPurify.** Rejected: a new dependency, a new licence entry and a new minified file for a problem that a short allow-list over the converter's own output solves.
6. **Make the document viewer's highlight tags a fixed pair.** Rejected: `hl.simple.pre` and `hl.simple.post` are settings of the panel, and dashboards use other tags.

## Decision

Each sink gets two layers, an escape that keeps only the markup the code itself adds, and then `ng-bind-html`, which sanitizes.

- **One shared set of helpers in `kbn.js`.**
  - `kbn.escapeHtml` (from 0014) escapes a value for HTML text or an attribute.
  - `kbn.highlightHtml(text, pre, post)` escapes the text and keeps only the exact `pre` and `post` strings, which are the tags Solr was asked to put around a match. Anything else, including other markup of the document, becomes text. An array is joined without a separator, as the page did when it put an array of strings into an element.
  - `kbn.isSafeUrl(url, schemes, dataImages)` allows an address with one of the given schemes, or without a scheme (a relative address or a `#` anchor, which cannot run script). Control characters and spaces are removed before the scheme is read, which is more than browsers drop (only tabs and newlines inside a URL, and leading and trailing control characters and spaces), so the check errs on the safe side.
  - `kbn.safeMarkdownHtml(html)` is the check for the converter's output (below).
- **Highlight tags.** The panels ask for highlighting in three ways, and each keeps only its own tags. The document viewer sends `hl.simple.pre` and `hl.simple.post` from its settings (default `<mark>` and `</mark>`) and now keeps exactly those. The full text search panel asks Solr for its default `<em>` and `</em>` and keeps exactly those, shown with the same styled span as before. The table panel uses the markers `@start-highlight@` and `@end-highlight@`, which its filter already turned into `<code class="highlight">` after escaping.
- **Document viewer.** Title and content: `ng-bind-html="... | highlightHtml:panel.simplePre:panel.simplePost"`. Because the configured tags are part of the dashboard and a dashboard can be written by someone else, the sanitizer still runs over the result. A configured tag therefore keeps the elements and attributes that `$sanitize` allows (`class` is allowed, `style` is not).
- **Full text search.** The highlighted body goes through `kbn.highlightHtml` with `<em>`; the body without highlighting is escaped (`noXml`) after it is shortened, so that a shortened value never ends in half an entity; the values in the details table are bound with `ng-bind-html`.
- **Table.** The hyperlink columns are escaped (`noXml`) before the filter that turns addresses into links, and bound with `ng-bind-html`. The `noXml` filter also turns an object into escaped JSON; before, an object went through `stringify` unescaped, so a nested value in the details table was written as raw JSON text. The values in the details table are bound with `ng-bind-html`. A new `htmlString` filter turns a number or an array into a string, because `ng-bind-html` accepts only a string. The image column keeps `ng-bind-html-unsafe`, because the `<img>` it builds needs a `style` for the configured size and may hold a relative or `data:image` address, all of which `$sanitize` removes. What it builds is safe by construction: the address is recovered from the escaped text, shown as plain text unless it has no scheme or uses `http`, `https` or `data:image/...`, and escaped again for the attribute together with the configured width and height. Every other column value is escaped by `tableHighlight` before it reaches that binding, and the only markup in it is the filter's own highlight tag.
- **Text panel markdown.** The source is escaped as before, Showdown converts it, and the result is made safe with `kbn.safeMarkdownHtml` before it goes into the element. That function parses the HTML in a document that never runs script or loads images, keeps only the elements and attributes that the converter produces (`a`, `img`, `p`, headings with an `id`, `pre`, `code` with a `class`, lists, `em`, `strong`, `blockquote`, `hr`, `br`), unwraps or drops everything else, and writes it out. A link may use `http`, `https` or `mailto`; an image `http`, `https` or a `data:image/` address; an address without a scheme is kept in both, so links to another dashboard (`#/dashboard/solr/Home`) and to a path on the same server keep working. This also admits protocol-relative addresses (`//host`, `\\host`), which reach another server over http or https; they cannot run script. An address with any other scheme loses its `href` or `src` and the link text is kept. A double quote cannot add an attribute because the attributes are read from the parsed document and written back escaped. `id` and `class` values are kept only when they hold letters, digits and `_ : . -`. The markdown test drives the real `markdown` directive of the text panel: it compiles the element, waits for the converter to load and checks the rendered DOM. The inspector's markdown filter is unchanged: it is bound with `ng-bind-html`, so `$sanitize` already applies.
- **Alerts.** The alert container is bound with `ng-bind-html`, so alert text is sanitized when it is shown, and every value in an alert text that comes from a dashboard, a list or a response is escaped with `kbn.escapeHtml` where the alert is built, as 0014 started for the failed-request alerts. The two layers do not double escape: `$sanitize` decodes entities in text and encodes them again, so an escaped `&lt;b&gt;` is shown as `<b>`. The changed alerts are: "Local Default Set", "Dashboard Saved", "Dashboard Deleted", "Dashboard Not Found" and the gist link in both `dashLoader.js` and the dashboard control panel. The rule for a new alert is the one in 0014: escape what you quote; markup you write yourself is limited to what `$sanitize` keeps (links with `http`, `https`, `ftp`, `mailto` or `#` addresses, `<i>`, `<b>` and the like).
- **Axis labels.** The axis label option of flot's axis label plugin is written into the page as HTML. The histogram (mode, time field), time series (metric, field, time field) and range facet (range field) panels pass values from the dashboard, so each is escaped with `kbn.escapeHtml` where the option is set.
- **Typeahead menus.** Bootstrap's typeahead writes each suggestion into its menu as HTML, and its highlighter does not escape. Suggestions come from dashboards (the query history of the derive queries panel) and from documents and the server (field names from the schema and from dynamic fields, collection names). The application replaces the highlighter once, in `components/typeahead-escape.js`, which every `bs-typeahead` input uses: it escapes each part of the suggestion and wraps the part that matches what was typed in `<strong>`, as before. The value that is chosen is read from the item, not from the menu, so it is unchanged. The vendored Bootstrap and AngularStrap files are not edited.
- **Empty labels.** `kbn.escapeLabel` is `escapeHtml` for a label that may be missing: a missing or empty value stays missing, so an axis without a label is still without one.
- **Tooltips.** The query alias or query text in the tooltips of the time series, histogram and range facet panels, the series colour field and coordinates in the scatter plot, the labels in the heat map, the name in the sunburst, the label of a map marker, the value in the field-list tooltips of the table and full text search panels and the query tooltip of the query panel are escaped.

### Values that reach markup in a role other than text

Searching for HTML sinks missed colours, because a colour is not text: it is written into a `style` attribute. The question to ask of every value from a dashboard or a document is where it ends up, not only whether it is shown. The sweep for values in a non-text role (colours, sizes, class names, style values, ids), by reading every template and every string in the code that builds markup:

- **Colours written into markup by code** (tooltip dots and inline styles in the histogram, time series, range facet, terms and Hits panels): fixed with `kbn.safeColor`, above. The first version of that function trusted the browser's own serialisation of the parsed colour, which an audit showed is not safe: it keeps `var(--a,"...")` as written. The function now accepts a fixed set of forms only. Also the colours a terms or significant terms panel takes from field values.
- **Scatter plot tooltip colour:** comes from a d3 colour scale over the colour field, so it is a colour from a fixed palette, not the value. Left.
- **Sizes and ids written by code:** the colour dot's size is a constant from the call sites (and is now read as a number); the heat map's element id is a counter the code generates; the `<span class>` of highlighted JSON is one of five fixed names.
- **Values written through attribute interpolation (`{{ }}` inside `style`, `class`, `href`, `id`, `ng-style`, `ng-class`):** the query colour in the ticker panel and the Hits panel's legend and list (`style="...{{query.info.color}}"`) and the filter colour choices, the panel and row heights and overflow, the panel span, the alert severity, the filter mandate, the facet fragment ids and the dashboard style name. AngularJS writes these with `setAttribute`, so a value cannot close the attribute or add an element, and it cannot run script; `href` values from data are rewritten to `unsafe:` by AngularJS 1.0.8 when they start with `javascript:`. What such a value can do is add CSS declarations (a height of `1px;position:fixed;...` overlays the page) or class names. That is the same in 1.6.30, a dashboard author already controls the layout of the page, and it is listed as a residual, not changed.

### Checking the list by running the code

Reading the code for places that write text into the page as HTML missed places three times, so `tools/hostile.js` (run as `npm run test:hostile` against a build) checks it by running the application. It serves `dist/`, loads a dashboard in headless Chromium against stubbed Fusion responses, and puts a payload in every string that a document, the schema, the server or the dashboard can supply: every document field value, field names (including field names that are themselves payloads), facet terms, pivot values, highlight snippets, the field list from the schema and from dynamic fields, collection names, saved dashboard names and ids, the user name, stream results, the gist address, and in the dashboard its title, row and panel titles, the text panel content in each mode, the query alias and text, a filter value, the hyperlink header and the derive-queries history. Each payload calls `window.__d3canary(N)` and a table says where number N was placed, so a failure names its source. Two payload styles run: markup (`<img src=x onerror=...>` followed by a `" onmouseover=...` attribute break-out) and a `javascript:` address.

Then it uses the page: it shows every tooltip, sends hover events to every flot chart (with a constructed point) and mouse events to every d3 mark, map region and marker, opens every table row and each of its views, pages the document viewer, opens every panel's editor and every tab, types five different queries into every typeahead (each is tried alone, because Bootstrap's highlighter wraps what was typed in `<strong>` and a query that falls inside a payload cuts the tag in two and hides it), opens the other dialogs (dashboard settings, row editor, new dashboard), and runs the dashboard menu actions that raise alerts (set default, save, list, gist, delete). The run also puts a payload in the colour of a query (plain, and inside `var()`, `env()`, `calc()`, `attr()` and `color-mix()`, which Chromium keeps verbatim), and the same inside colour terms, adds a colour-with-a-comment term to every facet, and turns on field values as colours in the terms panel. In a second pass it sets each string setting of each panel (one at a time, down two levels, and string arrays) to a payload, refreshes, and restores it. After every step it fails if the canary ran, if any element has an event-handler attribute that carries a canary, if any `href`, `src` or similar holds a `javascript:` address, or if an `<img src=x>` appeared.

The run also fails when nothing rendered: it checks floors on how many panels, payload texts, typeahead items, tooltips, canvases, svg marks and alerts it saw, and a panel that does not finish loading is a failure.

The run found two places that reading had missed: the typeahead menus, and the tooltip that the histogram and time series panels show for the hovered point (a second tooltip next to the one fixed earlier, which used the alias without escaping). An audit then found the chart colours, which the first version of the run did not exercise because it put no payload in the query list; the run now does, and walks `services` as well as the panels. It also showed that the run itself can fail to see a leak: the first version typed several queries in a row and checked only after the last, and the last one hid the payload from the earlier ones. Replacing the typeahead escape, the axis-label escape or the alert binding with their old code makes the run fail and name the payloads ("dynamic field name", "schema field name", "collection name", "query history", "setting of panel ...: mode", "dashboard title").

What the run cannot reach, so that nothing in this list is claimed as covered:

- Only the Fusion mode is run (`USE_FUSION` true). The Solr-mode field list (`/admin/luke`, `/schema/fields` in the Solr shape) and the Solr collection list use different response shapes and code, and are covered by reading and by the unit specs only. They end in the same typeahead and field-list bindings that the run exercises.
- Hover is simulated: flot is sent `plothover` with a point built from the plot's own first series, d3 marks get dispatched mouse events, and a leaflet marker only exists if the stubbed map layer draws one (map tiles are refused). A tooltip whose handler needs a different shape of point, or a marker that is not drawn, is not exercised. The unit specs drive the histogram and time series tooltips and the pie labels directly.
- Popovers (the field value lists of the table and full text search field lists) are not opened. Their text is bound with `{{ }}`, and their tooltips use the expression that is unit tested.
- Settings are set one at a time after the dashboard has loaded, only for strings and arrays of strings down two levels, and for the strings of the query and filter lists (a query's colour and alias, a filter's value), after which every tooltip is shown again. A setting that must be valid for the panel to draw (a mode, a chart type) is replaced by a payload and the panel then draws nothing; the markup it would have drawn with a valid value is covered by the data half of the run, not by that setting.
- Loading a dashboard from the address bar (`#/dashboard/file/<name>`, `solr/<name>`), uploading a file, and loading a gist run code that quotes the name in an alert; those alerts are escaped and unit tested, not run here.
- CSS and class names that attribute interpolation can add (panel heights, overflow, the ticker and Hits legend colours, filter colour choices): not script, same as 1.6.30, not changed; the run does not look for them.
- Downloads (CSV, XML, JSON export), the add-panel list, and anything that needs a real person's keyboard or drag are not run.
- Panel types that a dashboard can name but that are not in `panel_names` are run for `derivequeries` and `template`; `dashcontrol` has no panel template.
- A stub is a stand-in: nothing here shows what a real Fusion sends. A real response can hold strings in places the stub does not (a field type name, an error message) that a panel writes into the page; the library list above is where those would have to be found.

### Libraries that panels call

For each library the code was read for options and callbacks that end in `innerHTML`, `.html()`, `.append(string)` or `document.write`, and each panel call that reaches one was traced.

- **flot (`jquery.flot.js`).** Tick labels are written as HTML, but they come from numbers and from the time formatter with a format chosen from the interval (no document text); no panel sets `tickFormatter`. Legends are off in every panel. Reachable and fixed: the axis label plugin (axis labels above) and the pie plugin's label formatter (pie labels above). The selection, stack, stack percent and time plugins write no HTML.
- **AngularStrap (`angular-strap.js`) and Bootstrap.** Tooltips and popovers show their title as HTML; every tooltip with a value from data is escaped (table above). Popover and modal bodies are templates from the code. `bsAlert` is not used.
- **AngularJS and `ngSanitize`.** `ng-bind-html-unsafe` remains only on the table's image cell (safe by construction, above) and in an HTML comment. `ng-bind-html` sanitizes.
- **jQuery.** `.html()`, `.append()` and `.prepend()` calls in `src/app` are listed in the table above; those that take data are escaped.
- **jQuery UI.** Used for drag and drop of panels; writes no HTML from data.
- **d3 (and the sankey, force, shape and other modules).** `.html()` calls with data (scatter plot, heat map, sunburst tooltips) are escaped; the bar panel's tip shows a number; the other panels write data with `.text()`, which is text.
- **d3 tip (`d3.tip.js`).** Used only by the bar panel with a fixed template and a number.
- **d3 layout cloud.** Words are drawn with `.text()`.
- **vis network.** Reachable: the node `title`, which vis writes with `innerHTML`; fixed. The node `label` is drawn on a canvas as text.
- **Leaflet and its label plugin.** Reachable: the marker label, which the plugin writes with `innerHTML`; fixed. No popups are used.
- **jVectorMap.** Region labels are written from the bundled map data (fixed region names); the panel passes only numbers, and its `onRegionLabelShow` callback uses `.text()`. Not reachable with document values.
- **Bootstrap typeahead.** Reachable: the menu items are written with `.html()` and the stock highlighter does not escape. Fixed once for every input (above).
- **x2js.** Parses the graph panel's XML into objects; it writes nothing into the page. The titles it returns reach vis, which is handled above.
- **angular-dragdrop.** Wraps jQuery UI draggable and droppable for the panel and row handles; it reads JSON from attributes the code writes and writes no HTML.
- **Showdown.** Fixed (markdown above).
- **Underscore.** `_.template` is not called in `src/app` for data.
- **Bootstrap date and time pickers, moment, FileSaver, the Solr and Elasticsearch clients.** They write no HTML from document or dashboard values (the pickers format dates; the clients only send requests).

## Consequences

- What a person sees for legitimate content is unchanged: matches are highlighted, links to web pages, mail addresses and other dashboards are clickable, images from web addresses and embedded images show, markdown headings, lists, emphasis and code render, and alerts show their links.
- Field names, modes, metrics and time fields that look like HTML now show as text in axis labels, in the typeahead suggestions of every editor, and in the tooltips. A value that is only empty or missing keeps an empty label.
- What changes for content that was never meant as markup: a document whose field holds HTML is now shown as the text of that HTML in the document viewer, in the full text search body and in the details table, where 1.6.30 rendered it (or rendered it after sanitizing, in the highlighted full text search body). A term in a pie slice label or a graph node title that holds HTML is shown as text too. An image-column value with a scheme other than `http`, `https` or `data:image` is shown as text and not as a broken image. Text next to an address in a hyperlink column is escaped.
- The document viewer's highlight tags keep only what `$sanitize` allows. A dashboard that uses `<span style="...">` as its highlight tag loses the style; `class` works. This is a deliberate limit: the tags are part of a dashboard that other people can write.
- A value shortened by the full text search panel's truncation (shortened before highlighting, as in 1.6.30) can end in a cut-off `<em` or `</em`, which is now shown as text instead of being dropped by the browser. It is rare and only visible at the end of a shortened snippet.
- Markdown in the text panel is unchanged for everything it rendered before except the addresses described above. A `>` at the start of a line still does not make a blockquote, because the source is escaped before the converter runs, as in 1.6.30.
- `$sanitize` shows an `<img>` element from alert text, without an address; the alerts that quote a value escape it first, so this only matters for a future alert that forgets to.
- Further sinks added later must use these helpers. A test per sink renders the real template, controller, directive or filter with values that look like HTML (`<img src=x onerror=...>`, `" onmouseover=`, `javascript:`) and checks the DOM; see `test/unit/safeRenderingSpec.js` and `test/unit/chartLabelsSpec.js`. The exceptions are listed in the next item. The axis labels, the pie labels and the point tooltips of the histogram and time series panels are tested through the real chart directives of their panels, the typeahead menus through a real `bs-typeahead` input, and every sink above is also exercised by `tools/hostile.js` within the limits stated there.
- Not covered by a test: the graph node title (it is built inside the panel's link function, which needs a vis network), the chart tooltips of the range facet, scatter plot, heat map and sunburst panels and the map label, whose escaping is one call to `kbn.escapeHtml` each and needs a rendered chart or map to observe. They have no unit spec; `tools/hostile.js` reaches them with simulated hover, within the limits listed above, and they were reviewed by reading the code. The popover bodies and the Solr-mode field and collection lists have neither.
- Not proven here: the behaviour in the application served by Fusion. The specs run the real templates and controllers in a browser, not the page of a Fusion admin UI.
