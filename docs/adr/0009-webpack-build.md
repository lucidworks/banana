# 9. Build with webpack 5, keeping the AMD modules

Date: 2026-11-06

Status: Accepted. Partly superseded: the consequence about the WAR route is superseded by [ADR 0026](0026-remove-war-build.md) (the WAR build was removed), and the statement that no `engines` field is set by [ADR 0013](0013-committed-lockfile-and-node-range.md).

## Context

The old build was Grunt 0.4 with RequireJS's optimizer (`r.js`), `ngmin`, `uglify`, Bower and Babel 6, run as `grunt build`. It does not run on a maintained Node.js release: the Grunt command line is no longer installed, the linter rejects the sources, the optimizer cannot find `vis` and `x2js` (Bower installed them where the build did not look), the minifier cannot parse the ES2015 arrow functions that the graph and heatmap panels use, and the Babel dependencies were never wired to a task. The minifier also removed every third-party licence notice and stamped one banner over the whole bundle.

Banana's 69 application modules are written as AMD (`define([...], function (...) {})`) and load panels on demand through computed module ids. AngularJS 1.0.8 injects services by parameter name, so the code must be annotated before it is minified.

An experiment built a slice of the application (the whole non-panel app and four panels) with both candidates described below, rendered it in headless Chromium under `/`, `/banana/` and `/admin/banana/`, and measured the source changes each one needs.

## Options considered

1. **Keep Grunt and RequireJS, and repair the toolchain in place.** It can be made to build on a current Node.js with the 1.6.30 plugin versions, and it keeps the loader exactly as it was. Rejected: it keeps an unmaintained toolchain that has no support for current Node.js, and it needs separate repairs for `vis`, `x2js`, ES2015 and licence notices anyway. It stays as the fallback if the chosen bundler had failed.
2. **Vite (Rolldown), after converting every AMD module to an ES module.** Its dev server starts faster. Rejected for now: the slice needed 35 modified files (472 lines) against 3 files (10 lines) for webpack, a bundle is one strict-mode ES module so sloppy-mode vendored scripts behave differently (Modernizr stopped working at start-up), it rewrote the repository's legacy stylesheets unless they were moved out of the source tree, and it needed extra steps to keep licence comments. Converting the modules to ES modules remains possible as a later, separate change, and nothing in this decision prevents it.
3. **webpack 5, reading the AMD modules as they are.** Chosen. webpack understands `define` and `require` natively. Every `paths` and `shim` entry of the old RequireJS configuration that the application uses has a direct equivalent (the unused entries for angular-cookies, loader, mocks, resource, route and touch have none).

## Decision

`npm run build` runs `webpack --mode production` (see `webpack.config.js`) and then `tools/check-dist.js`, and writes `dist/`.

- **Layout.** The application is `app/app.js` (stamped with a content hash in `index.html`), and every panel is its own chunk under `app/chunks/`, together with its `module.html` template. `output.publicPath` is `auto`, so all asset and chunk URLs are relative to the script that loads them, and the same `dist/` works under `/`, `/banana/` and `/admin/banana/`.
- **`config.js` and `config.solr.js`** are copied into `dist/` byte for byte and are not bundled, so an operator can edit or replace them, or copy the Solr preset over `config.js`, without a rebuild. `config-boot.js` is loaded before `config.js` and holds on to the `define(['settings'], ...)` call that `config.js` makes; `components/config-bridge.js` runs it with the bundled settings class. The old build's cache-busting tag on `config.js` is gone: `config.js` is requested without one.
- **Loading panels.** `kibanaPanel.js`, `addPanel.js` and a few panels call `$scope.require` with computed ids such as `panels/<name>/module` and `text!panels/<name>/module.html`. A bundler cannot see through that, so `components/lazy-require.js` replaces the RequireJS context that `app.js` handed to `$rootScope.requireContext`. It maps each id shape to an `import()` that webpack can follow. An id that is not listed is rejected with an error.
- **Vendored scripts** that are plain scripts rather than modules (jQuery, AngularJS, Bootstrap, the flot plugins, Leaflet and others) get the equivalent of a RequireJS `shim` entry from `tools/webpack/vendor-loader.js`: dependencies load first, the script runs with `this` set to `window` and with module detection switched off, and the global it creates is exported. The table is in `webpack.config.js`. Libraries written as UMD (the d3 family, `vis`, `x2js`) are left to webpack, which uses their AMD or CommonJS branch, as RequireJS did.
- **AngularJS annotation.** `babel-loader` runs `babel-plugin-angularjs-annotate` over `src/app` and over the vendored AngularJS add-ons, before minification. This replaces `ngmin`. If it is missing the build still succeeds but the page fails at run time with "Unknown provider", so the build check and the smoke check below both test for it.
- **ES2015.** The 1.7.0 panels use arrow functions. The minifier parses them and the output keeps them, and the webpack runtime code is ES2015 too; there is no transpile step, so the build targets browsers that support ES2015. The 1.6.30 build output was ES5 and ran in older browsers, so this raises the minimum browser for the built application to the one the 1.7.0 panels already needed.
- **`vis` and `x2js` come from npm** (`vis` 4.21.0, as Bower pinned it, and `x2js` 3). `x2js` 3 renamed its parsing method, so `panels/graph/module.js` calls `xml2js(...)` instead of `xml_str2json(...)`; the `_` prefix on attribute names is unchanged. This was verified only on synthetic GraphML.
- **Licences.** Third-party licence comments are kept, and `THIRD-PARTY-LICENSES.txt` is written into `dist/`. It lists the npm packages that are bundled and every library vendored as source, using `tools/vendor-licenses.json`, which holds each library's name, version, licence and copyright, and quotes the notice at the top of each file. The minifier only keeps `/*!` comments and can still lose one by merging statements, so the vendor loader copies the header comments of every vendored file in front of it as `/*!` comments. Nothing is stamped with a copyright holder.
- **Build check (`tools/check-dist.js`).** It fails when a script in the output calls `eval(`, and when a panel is missing: every name in `panel_names` in `config.js` and every directory under `src/app/panels` must have its module chunk and template chunk in `dist/`. It also fails when a file that is fetched by URL at run time is missing, when `config.js` or `config.solr.js` in `dist/` differ from `src/`, when `index.html` has an absolute URL, when a component is registered without annotation, and for the licence rules: every file under `src/vendor` with a licence header must be listed in `tools/vendor-licenses.json`, and every listed library must be in `THIRD-PARTY-LICENSES.txt` and keep its header in the output.
- **Browser smoke check (`tools/smoke.js`, `npm run smoke`).** A green build can still produce a dead page. The script serves `dist/` under each of the three base paths (answering 404 outside the base path), opens it in headless Chromium against stubbed Solr and Fusion responses, and checks that AngularJS starts, that `config.js` was applied, that every panel type in `config.js` loads and renders, that the charting panels draw (including the ones that load extra scripts on demand: the flot pie plugin, the jVectorMap data files and the Leaflet plugins), and that there are no page errors, console errors or failed requests. The stubbed responses are synthetic, not recorded from Fusion. Playwright is a development dependency; it does not download a browser when it is installed, so run `npx playwright install chromium` once (the `PLAYWRIGHT_BROWSERS_PATH` variable chooses where it is kept).
- **Dev server.** `npm run dev` serves the application with webpack-dev-server, bound to 127.0.0.1 (set `BANANA_DEV_HOST` to listen elsewhere). Set `BANANA_DEV_PREFIX` (for example `/admin/banana/`) to serve it under a base path. It does not proxy `/api` or `/solr`, so it shows the interface but cannot reach Fusion or Solr unless a proxy is added.
- **Removed.** `Gruntfile.js`, `bower.json`, RequireJS (`src/vendor/require/` and `src/app/components/require.config.js`), the `grunt`, `grunt-*`, `bower`, `requirejs`, `rjs-build-analysis` and Babel 6 (`babel-cli`, `babel-preset-env`) development dependencies. The Karma configuration and its dependencies stay for now and are replaced by a separate change; they did not run on current Node.js before this change either.

Source changes needed by the bundler:

| File | Change |
| --- | --- |
| `src/index.html` | Loads `config-boot.js`, `config.js` and `app/app.js` instead of RequireJS. |
| `src/app/app.js` | Takes `components/lazy-require` where it took RequireJS's `require`. |
| `src/app/panels/graph/module.js` | `x2js` 3 method name, as above. |
| `src/app/panels/bettermap/module.js`, `heatmap/module.js` | Dropped the module-local `require` and `requireContext`; the application loader resolves `./leaflet/plugins`. |
| `src/app/panels/map/module.js` | The map data file id was resolved against the application base URL, which only RequireJS did; it now goes through `lazy-require`. |
| `src/app/panels/terms/module.js` | Loads the flot pie plugin through `lazy-require`. |
| `src/app/panels/tagcloud/d3.layout.cloud.js` | Always adds the layout to `d3`. A bundler defines `module` for AMD modules, so the CommonJS branch that was there exported the layout instead. |

## Consequences

> Update, 2026-11-07: some statements below have been overtaken. The WAR route no longer exists ([ADR 0026](0026-remove-war-build.md)). `package.json` now has an `engines` field ([ADR 0013](0013-committed-lockfile-and-node-range.md)). The Karma harness was replaced as announced ([ADR 0010](0010-unit-test-harness.md)). The file counts and the note about `NOTICE.txt` describe the build when it was introduced; the notice file is now `NOTICE` ([ADR 0011](0011-licence-and-notices.md)). The tag cloud's stop-word list now loads ([ADR 0031](0031-unreleased-panel-features.md)); the map panel's `countryCodes` lookup still fails as described.

- The build needs a current Node.js. Babel 8 needs 22.18 or later, and webpack-dev-server 6 needs 22.15 or later. No `engines` field is set here; it should be set when the dependency versions are pinned.
- **`src/` cannot be served as it is any more.** It used to run in a browser under RequireJS (the README and QUICKSTART described copying `src` into a Solr web app). Now `dist/` is what runs, so the README, QUICKSTART and the Solr 4 and 5 instructions say to build first and copy `dist`. A raw `src/` served by any web server shows a blank page. `npm run dev` serves the built application, not raw sources, and it does not proxy `/api` or `/solr`, so it is a way to work on the interface, not a way to host Banana. The root `index.html` landing page and `npm start` now point at `dist/`.
- **The WAR route changes.** `build.xml` and `default.properties` used to package `src/` into the WAR. They now package `dist/`, so `npm run build` has to run before `ant`, and `ant` stops with a message when `dist/index.html` is missing. This change was made by editing the descriptors and checking that they are well-formed XML; Ant and Maven were not available, so the WAR itself has not been built or deployed. The Maven descriptor (`pom.xml`) declares `src` as a Java source directory but packages nothing from it, so it is unchanged.
- **Panels are fixed at build time.** Panels are bundled into chunks, and `components/lazy-require.js` only knows the chunks that existed when the build ran. A panel directory or a `map.<name>.js` file that is added to a deployed `dist/` is not picked up; rebuild instead. 1.6.30 loaded such files at run time.
- Stylesheets and HTML templates are copied or bundled as they are, with no CSS or HTML minification (the old `cssmin` and `htmlmin` steps are gone), and the linting step that ran inside `grunt build` is not part of the build. The existing sources do not pass the linter's current rules, so a lint step would be a separate decision.
- The Grunt `distribute` task, which produced zip and tar archives, is gone. Producing archives is left to a later change.
- `dist/` has 193 files, against 172 in the 1.6.30 build output. 79 paths of the 1.6.30 output are gone, mostly the per-panel `module.js` and `module.html` files, the `map.*.js` data files and `require.js`, which are now bundled into chunks or no longer needed; 100 paths are new (the chunks, licence files and hashed bundle). Unused vendored files that 1.6.30 copied, such as `timezone.js`, are no longer shipped. `dist/` still holds everything that the application fetches by URL.
- Neither smoke check nor build check proves behaviour against a live Fusion; only synthetic responses were used.
- Known issues that this change did not touch: the map panel reads `worldmap.countryCodes` and the tag cloud reads `stopwords` from files that export nothing, so those two lookups fail when they run, as they did in 1.6.30; `NOTICE.txt` still describes the old tools.
